# Pool Website Redesign Brief

You are the lead design engineer on a full visual redesign of poolapp.co. Your client rejected the current site because it looks like it was generated by an AI site builder in one prompt (it was — v0). Your job is to make it impossible to mistake this site for anyone else's. Read this entire brief before touching anything.

## Scope: frontend only — hard boundary

This is a visual redesign and nothing else. Do not touch: API routes or server logic, form fields/validation/submission handlers, third-party integrations or analytics snippets, environment variables, existing routes or SEO metadata, deployment config, or `package.json` beyond what fonts require (`next/font/google` needs no install). The test for every change: if it could alter *behavior* rather than *appearance*, it's out of scope. Fixing the duplicated section DOM is in scope (it's markup), but any content or wired-up logic inside those sections must survive intact.

## What Pool is

Pool is a social network for people who spend time — and money — together. Friend groups create a pool around the things they actually do (roommates, brunch crew, ski trip, everyday coffee run), fund it together, and everyone gets a card that spends from it. Spending shows up in a shared social feed. No IOUs, no chasing people down, no awkward math after.

Pool is **not** a bill-splitting app, an expense tracker, or a fintech tool. It should never look or sound like one. The card is the plumbing; the group is the product.

Audience: 18–35, social, group-chat-native. The site's single job: make a visitor feel "this is fun and my friends need it" and pre-register for the beta.

## Diagnosis of the current site

- Generic v0 skeleton: centered hero → three icon cards → three more icon cards → CTA. Could be any SaaS product.
- The copy is actually good and stays (see Copy section). The visuals communicate nothing.
- Logo is a PNG dropped into a default nav. No brand color, illustration, or motion anywhere.
- Sections render duplicated content in the DOM (likely a carousel + grid both mounted). Fix this.
- Keep the existing Next.js stack, routes, and form logic. This is a reskin-and-elevate, not a rewrite.

## Brand system

The brand assets (see `/brand-assets` if present in repo, otherwise the descriptions here are authoritative) define a **sticker-pop** world: a kiddie pool with three stacked rings (blue/yellow/pink), money splashing in, thick navy outlines on everything, flat fills, no gradients on illustration. Think enamel pins and Saturday-morning cartoons, executed with adult restraint.

### Color tokens (fine-tune by sampling assets if present; these are the starting values)

```css
--pool-blue:   #4EC3F5;  /* top pool ring, links, sky sections */
--pool-yellow: #FFCE3E;  /* middle ring, primary buttons */
--pool-pink:   #FF77B0;  /* bottom ring, action accents */
--pool-green:  #63C666;  /* dollar bills, success states */
--pool-gold:   #F5B63C;  /* coins */
--navy:        #14224A;  /* ALL outlines, text, hard shadows */
--cloud:       #FDFCF9;  /* page background — warm off-white */
--sky-tint:    #EAF7FE;  /* alternate section background */
```

Rules: navy is the only text color on light backgrounds. Never use gray text — use navy at reduced opacity if hierarchy is needed. No gradients except, at most, a barely-there radial warmth behind the hero. Color is applied in big flat confident areas, not scattered accents.

### The unifying device: sticker construction

Every interactive or card-like element is built like a die-cut sticker:

- 2–3px solid navy border
- Hard offset shadow: `box-shadow: 4px 4px 0 var(--navy)` — never soft blurred shadows
- Generous border-radius (12–20px; pills for buttons)
- Hover: lift (`translate(-2px,-2px)`, shadow grows to 6px)
- Active: press (`translate(2px,2px)`, shadow collapses to 0)

This one device, applied consistently, is what makes the site cohesive and un-templated. Buttons: yellow primary, blue secondary, pink for the pre-register CTA.

### Typography

- **Display:** a chunky rounded face that echoes the bubble-letter wordmark — Baloo 2 (700/800) or Fredoka (600/700). Load via `next/font/google`. Used for H1/H2 and the wordmark only.
- **Body:** a clean friendly sans — DM Sans or Inter. Never use the display face for paragraphs.
- Hero H1 gets the sticker treatment: navy outline + slight hard shadow (SVG text with `paint-order: stroke` or layered text-shadow).
- Replace whatever default font the v0 scaffold ships (likely Geist).

### Rebuild the brand marks as SVG

Do not scale the PNG logo. Recreate as inline SVG components, matching the asset style (thick navy outline, flat fills):

`<PoolMark>` (3-ring pool), `<Coin>`, `<Bill>`, `<Droplet>` (blue/yellow/pink/green variants), `<Splash>` (the Y-shaped burst), `<Cloud>`, and the wordmark with multicolor letters (P blue, first O yellow, second O pink, L green) with navy outline. These become your illustration vocabulary for the whole site. If individual exported assets exist in the repo, trace/match them; otherwise draw from the descriptions above.

## The signature: an interactive hero pool

Spend the boldness budget here. One orchestrated moment, everything else disciplined.

**The scene:** the three-ring pool sits large on the right (stacked below the headline on mobile), filled with bills and coins. An ambient loop plays: a bill flutters down every few seconds, lands with a small splash; droplets arc out; an occasional coin drops with a satisfying plink of motion. Clouds drift very slowly in the background.

**The interaction:** clicking/tapping anywhere in the hero tosses a coin from the click point into the pool — small arc, splash on landing, and the coin visibly stays, so the pool gets richer as you play. Cap the visible pile (~30 coins), then recycle oldest. On touch devices, tapping the pool itself triggers it.

**Implementation constraints (hard rules):**

- Inline SVG scene + WAAPI/CSS transforms. No physics library. Coin arcs are precomputed cubic-bezier paths with slight randomization.
- Max ~10 concurrently animating elements; splash sprites live <600ms then are removed from the DOM.
- Animate `transform`/`opacity` only. Pause the ambient loop when the hero is offscreen (IntersectionObserver) or tab is hidden.
- `prefers-reduced-motion`: render the full static scene (pool, money, one frozen splash), no loop, click still adds a coin with no animation.
- This is a client component; render the static SVG on the server so there's zero layout shift on hydration.

Hero copy (keep, don't rewrite): H1 **"Pool. Tap. Done."** Subline: **"A social network for people who spend time — and money — together."** CTA: pink sticker button **"Pre-register for the beta"**, secondary ghost **"See how it works"** (smooth-scrolls).

## Supporting interactions — build exactly these two, exceptionally

1. **The feed demo.** A phone frame (drawn in the sticker style, not a photoreal device) showing a fake Pool feed that auto-plays a ~12s loop: "Maya started **Lake Weekend 🚤**" → Jordan and Sam avatar-chips join → "Sam added $50" with the pool balance ticking up → "Jordan tapped **$42 at Shell**" card slides in → 🔥 and ⛽ reactions pop on → "Maya tapped **$118 at Kroger** — 'we feast'" → comment bubble appears → loop. Cards animate in with transform/opacity, pause when offscreen, reduced-motion shows the full static feed. This section is titled with the existing line **"Shared Moments"** or lives inside "WTF Is Pool?!" — it is the single most important proof on the page because it *shows* the social layer instead of claiming it.

2. **The transaction ticker.** A slim marquee strip under the hero, CSS-animated (duplicated track, `translate3d`, pause on hover), of playful real-feeling entries: "🏖️ Beach House — Alex tapped $63 at Costco" · "☕ Coffee Run — Priya tapped $11" · "🎿 Ski Trip — Sam added $200" · "🏠 Apt 4B — rent day, everyone's in" · "🎂 Dana's Gift — goal reached 🎉". Sets tone in one glance and costs nothing in performance.

Nice-to-have only if the above are flawless: a small droplet burst on primary-button clicks, and section dividers drawn as a flat scalloped water edge with navy outline (in brand style — no soft gradient waves).

## Copy rules (hard)

- Keep verbatim: "Pool. Tap. Done." · "A social network for people who spend time — and money — together." · "WTF Is Pool?!" · "Ready to Jump In?" · "no IOUs, no awkward math, no receipts to chase."
- Do not invent new positioning or taglines. If you think a line could be stronger, leave the approved line in place and put alternatives in a code comment for Hussam to review.
- Banned words in feature copy: split/splitting, settle/settling, expense(s), tracking (as a feature), fintech, seamless, effortless, elevate, unlock, empower. ("No IOUs / no tracking" as negation is on-brand and allowed.)
- Voice: warm, direct, a little cheeky. Short sentences. Talk about crews, moments, and routines — never transactions, balances-owed, or "financial wellness."
- All demo/feed content uses the sample data in this brief — no lorem ipsum, no "John Doe."

## Performance budget (hard rules — the site must never feel laggy)

- Animate `transform` and `opacity` only. No animated `box-shadow`, `filter`, or layout properties. `will-change` sparingly and only on the hero.
- No animation libraries unless framer-motion is already installed — and even then prefer CSS/WAAPI for everything in this brief. No GSAP, no Lottie, no three.js, no particles library.
- All loops pause offscreen (IntersectionObserver) and on `visibilitychange`.
- `prefers-reduced-motion` fully honored everywhere: static scenes, no marquee, instant reveals.
- Brand illustrations are inline SVG (they're also your sharpest asset — no raster blur). Any remaining raster images: WebP, sized, lazy-loaded below the fold.
- Two font families max, subset via `next/font`, `display: swap`-safe with no visible layout shift.
- Remove the duplicated section DOM from the v0 scaffold; one responsive layout per section.
- Targets on the landing page: Lighthouse ≥ 90 across the board on mobile emulation, LCP < 2.0s, CLS ≈ 0, first-load JS for the route < 150KB gzipped.
- Accessibility floor: visible navy focus rings on everything interactive, 4.5:1 contrast for text (navy-on-yellow and navy-on-cloud pass; white-on-yellow does not — never do it), all decorative SVG `aria-hidden`, feed demo has a text alternative.

## Anti-slop checklist — if any of these appear, you've failed

- Indigo/violet/purple anything; gradient text via `bg-clip-text`; glassmorphism; blurred blob backgrounds
- Three equal cards with a lucide icon, bold title, and gray paragraph
- Soft `shadow-lg` on white cards over a gray-50 background
- Default shadcn/Tailwind look with untouched radii and slate text colors
- Emoji as heading decorations (emoji live inside feed/ticker content only, where they're diegetic)
- Centered everything; identical section rhythms; hero screenshot in a browser mockup
- Any copy that could describe a generic app ("Simplify your group expenses today!")

The test: screenshot any section, strip the logo, and it should still be unmistakably Pool.

## Process — one continuous run, no check-ins

Execute everything below in a single session, start to finish, and present the finished product at the end. Do not stop for approval between phases and do not ask questions the brief already answers. Work on a branch (`redesign/sticker-pop`) and commit at every phase boundary with a clear message, so any single phase can be reviewed or rolled back later without touching the rest.

**Phase 0 — Audit & plan (internal, no code changes).** Inventory the repo: framework version, routes, components, styling approach, installed deps, where the duplicated DOM comes from. If a dev server and screenshot tooling (e.g. Playwright MCP) are available, capture baseline screenshots. Write your plan — final token values, an ASCII wireframe of the landing page, your hero-scene approach — to `REDESIGN_PLAN.md` for the record, then proceed immediately.

**Phase 1 — Design system.** Tokens in CSS variables + Tailwind config, fonts, sticker primitives (Button, Card, Chip), SVG brand components, nav + footer. Also write the tokens, sticker rules, and copy rules into `CLAUDE.md` so every future session stays on-brand.

**Phase 2 — Hero.** The signature scene, ambient loop, coin-toss interaction, reduced-motion path, ticker.

**Phase 3 — Sections.** WTF cards, feed demo, How It Works, beta CTA. Secondary pages restyle.

**Phase 4 — Polish.** Micro-interactions, scroll reveals, mobile pass at 360/390/768/1280, cross-browser sanity (Safari especially — SVG animation quirks).

**Phase 5 — Performance & a11y.** Hit every number in the budget. Remove dead v0 code. Run Lighthouse and report the scores.

Because nobody reviews mid-run, self-verification is mandatory, not optional. At every phase boundary: confirm the build compiles and every route renders; if screenshot tooling exists, capture desktop and mobile screenshots and critique them against this brief (channel Chanel: remove one accessory), then fix what fails before moving on. Never mark a phase done on an unverified build.

Before finishing, review the full diff against the scope boundary at the top of this brief — if anything outside the frontend slipped in, revert it.

**Final deliverable.** End the session with: (1) the dev server running so the result can be viewed immediately, (2) a short per-section summary of what changed, (3) Lighthouse scores measured against the performance budget, (4) the alternate copy lines you left in code comments for review, and (5) anything you deliberately skipped or toned down, and why.
